# 설계 결정

바꾸기 전에 왜 이렇게 되어 있는지 확인할 것. 결정이 바뀌면 이 문서도 고친다.

## 결정된 것

### 경간 길이 (`utils/comom_util.py`)
- 측점의 최대 경간 = min(설계속도 한도(직선 또는 터널), 곡선 반경 한도). 곡선 한도는 설계속도와 무관하므로 저속 노선에서 완만한 곡선 경간이 직선보다 길어지지 않게 함께 제한.
- 경간 하나는 시작점·안쪽 25m 블록 경계·끝점(`span_check_points`) 중 가장 엄격한 한도를 넘지 않는다 (직선에서 시작해 급곡선·터널에서 끝나는 경간 포함). 이 규칙으로 충남선 전주 수가 1697 → 1699 로 바뀌었다 (의도한 변경).

### 25m
BVE 블록 단위. 곡선·구배·구조물이 블록마다 정의되므로 코드의 25 는 의도된 값이다.

### 에어조인트·흐름방지
- 자동 배치는 1600m 마다 에어조인트 (`core/runner.py`, `define_airjoint_section(airjoint_span=1600)`).
- 흐름방지장치는 에어조인트 사이 가운데에만 둔다. 사용자 추가/삭제 요청은 보관했다가 rebuild 마다 다시 적용.
- 다른 에어조인트 타입(3경간 등)은 당분간 추가하지 않는다 (사용자 결정). 추가할 때는 [extending.md](extending.md) §1.

### 복주 에어조인트
- 2·3·4호주는 같은 쪽에 앞·뒤로 선 전주 2개 (지지점 하나 = `PoleDATA` 하나 + `twin`). 간격은 실행 설정 UI 입력(기본은 데이터셋 `airjoint.double_pole.spacing` 1.0m).
- 쌍 전주의 기둥은 일반개소 기둥. 평행틀 없음.
- 급전선설비는 UI 에서 선택: 양 전주 / 앞 전주만 / 데이터셋 값.
- 전선 시작점은 지지점 측점 (각 전주 위치가 아님).
- 테이블은 `-F`/`-B` 두 행 (`1-39D-F`, `1-39D-B`), 각 행을 따로 선택·편집.
- 브래킷·전선 규칙은 단주와 같다 (`SectionType.AJD_*` → `role` 로 단주 값).

### 데이터 구조
- 편집은 전주 데이터만, 파생 값은 `rebuild` 하나로 다시 만든다 ([architecture.md](architecture.md)).
- `PoleDATA.next_*`·`span` 은 이은 다음 전주에서 계산하는 속성. 연결은 `.dat` 에 저장하지 않고 불러온 뒤 다시 잇는다 (pickle 재귀 한도).
- 좌표·계획고·곡선·구배는 `place_on_alignment` 한 곳에서.
- 구성품은 BVE 오브젝트 이름과 별개로 `role`·`spec` 을 갖는다. 도면 약어·물량표는 역할로 구분한다 (예: 250 데이터셋 일반 개소 브래킷은 `…-AJ-I` 오브젝트지만 역할은 가동브래킷).

### 출력
- 리팩터링은 BVE CSV 바이트 동일. 출력 변경은 의도한 것만, 기준 출력을 다시 기록하고 PR 에 이유를 적는다.
- 도면(평면도·종단면도)은 BVE CSV 와 같은 전주·브래킷 측점을 쓴다 (`bracket_stations`). 전선은 지지점 사이 직선으로 그린다.
- 미리보기 오브젝트는 사용자 Object 폴더 → 저장소 `assets/preview/`(공개해도 되는 배경·전철전력 라이브러리) 순으로 찾는다.
- 건축한계·선로중심선 미리보기 오브젝트는 사용자 DXF 에서 생성 (`tools/preview_objects.py`, `assets/preview/README.md`).

### 경로·설정
- PC 별 경로는 `~/.decatsbve/settings.json`. 코드에 절대 경로를 두지 않는다.
- 오브젝트 인덱스·치수는 데이터셋. 새 키는 `DatasetGetter` 기본값으로 구버전 커스텀 데이터셋과 호환.
